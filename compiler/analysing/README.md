# Lexical Analyzer – README

## Overview

This project implements a **modular lexical analyzer** for a small C‑like language.  The analyzer performs three main steps:

1. **Scanning** – tokenises the source file (`tokenize.c`).
2. **Analysis** – collects statistics, builds a unified **symbol table** with rich attributes (lexeme, type, scope, simulated address, function flag, frequency, line/column locations) (`analysis.c`).
3. **Reporting** – prints a human‑readable report that includes keyword/operator/identifier frequencies and a **combined symbol‑table**.

The code is deliberately split into small, single‑purpose modules (`scanner_helper`, `string_char_processing`, etc.) so each component can be built and tested independently.

## Building the Analyzer

The project uses a simple **Makefile**.  From the `analysing` directory run:

```bash
make clean   # (optional) removes previous object files
make         # builds `analyzer`
```

The generated executable is `analyzer` and will be placed in the same directory.

---

## Running the Analyzer

```bash
./analyzer <source-file.c>
```

The tool reads the source file, tokenises it, enriches the token information, and finally prints a report.

### Example commands

```bash
# Run on the provided sample program
./analyzer test_sample.c

# Run on the file that contains a multi‑line comment
./analyzer test_comment.c
```

---

## Modules & What They Do

| Module | Responsibility |
|--------|-----------------|
| `tokenize.c` | Lexical scanner – recognises identifiers, keywords, numbers, strings, operators and delimiters. Handles multi‑line comments (`/* … */`) by skipping them. |
| `scanner_helper.c` | Loads the source file into a mutable buffer, tracks line/column numbers. |
| `string_char_processing.c` | Helper functions for string literal handling and character classification. |
| `analysis.c` | Counts occurrences, assigns attributes (type, scope, address, function flag), and formats the final symbol‑table. |
| `main.c` | Orchestrates the workflow: reads arguments, invokes the scanner, passes tokens to analysis, prints the report. |

---

## Symbol‑Table Output (What You See)

The analyzer prints three sections:
1. **Keyword / Operator / Identifier frequencies** – simple counts with line numbers.
2. **Additional metrics** – number of pre‑processor directives, numeric constants, string literals, total tokens.
3. **Unified Symbol Table** – each entry shows:
   - `Lexeme`
   - `Type` (e.g., `int`, `float`)
   - `Scope` (currently `global` – can be extended to block‑level)
   - `Addr` – simulated memory offset (4‑byte slots for variables; `0` for functions)
   - `Func` – `1` if the identifier is a function
   - `Count` – total occurrences
   - `Lines` – `line:column` list of each occurrence

## Extending the Analyzer

* **Add new token types** – edit `token.h` and extend the switch in `record_token_analysis`.   
* **Block‑level scope** – maintain a stack of `{` / `}` levels while scanning and prepend it to the `scope` field.   
* **Parameter lists** – when a function identifier is detected, capture the token sequence between the matching parentheses and store it in `extra`.

Feel free to modify the modular source files and re‑run `make` – the build system will automatically recompile only the changed objects.
